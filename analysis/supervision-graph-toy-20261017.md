# 监督二部图的最小理论草案（development）

日期：2026-10-17  
状态：未审计理论草案；不是论文定理，不支持现有实验数字。

## 记号

令 (H) 为 hash 集合，(Y) 为答案集合，监督关系为二部图
(G=(H,Y,E))。令 (d_H(h)) 和 (d_Y(y)) 分别表示两侧度数。

| 配方 | (d_H) | (d_Y) | 图是否改变 |
|---|---|---|---|
| fixed | 1 | 1 | 基线 |
| 2tgt | 2 | 2（在配对规模匹配时） | 每个 hash 指向两个答案 |
| 2hash | 1 | 2 | 每个答案接收两个 hash |
| b128 | 1 | 1 | 图不变，只改变样本曝光 |

这张表只描述 incidence graph；它不等价于训练 token 数、optimizer steps 或 wall-clock。

## 可证明的受限命题方向

考虑共享参数的线性化模型

\[
f_\theta(h)=W\phi(h), \qquad
\hat\theta=\arg\min_\theta\sum_{(h,y)\in E}
\|W\phi(h)-u_y\|_2^2,
\]

其中 (phi(h)) 是 hash 的共享特征，(u_y) 是答案原型，训练标签含独立零均值噪声。
若同一答案的 (k) 个 hash 特征在给定设计矩阵下提供独立信息，并且设计协方差的最小
特征值有正下界，则该答案原型的估计方差随 (k) 降低，形式上为

\[
\operatorname{tr}\operatorname{Var}(\hat u_y)=O(1/k).
\]

在额外假设输出 margin 大于估计误差时，可把它转成未见 hash 输出合法答案的错误概率上界。
这个方向解释了为什么 `2hash` 可能比重复同一条边更有效：前者增加独立 hash 入口，后者只增加
同一观测的权重。正式证明前必须明确特征分布、噪声模型、答案原型如何共享以及“合法输出”
如何由 margin 定义。

## 必须同时保留的反例

若 (phi(h)=e_h) 是每个 hash 的独立 one-hot 特征，未见 hash 对应的列没有训练观测，
那么增加训练答案的 hash 入口不能改善未见 hash 的预测。因而“监督图更密必然提高创造力”
是错误的普适命题；任何正向理论都必须依赖共享表示、有限秩或平滑假设。

## 可检验预测

1. 在相同总训练行数下，`2hash` 应比 `repeat_rows_k2` 拥有更低的 unseen-hash 错误率，
   若共享表示是承重因素。
2. `b128` 的 incidence graph 与 `fixed` 相同；若两者差异很小，说明单纯 batch 曝光不足以解释
   `2hash` 的收益。
3. `memo_own` 仍高而 creativity 上升时，机制应表述为“查询到答案集合/共享答案原型”，
   不能表述为“减少记忆”。

这些预测需要在同曝光、同 token、同 checkpoint 选择和 fresh heldout 下测试；在实验完成前不应
把本草案写入论文的结论段。
